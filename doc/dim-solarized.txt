1. INTRODUCTION                                   *dim-solarized-introduction*

dim-solarized.nvim is a Solarized-based colorscheme with the original
Solarized dark background and accent hue balance. Chroma is generally
reduced; text and accents are lighter than the originals for readability.
"Dim" describes restrained emphasis, not lower lightness. It is dark only.

  - The 8 accents share the same lightness and chroma, except orange and
    magenta (slightly lighter), red (more chroma), and cyan (less chroma)
    (5.7-7.0:1 contrast against the background).
  - Body text and comments are brighter than in the original (comments reach
    about 5.2:1 against the background).
  - The palette is computed from CIE LCh in `lua/dim-solarized/palette.lua`.
  - Covers Tree-sitter groups, LSP semantic tokens, diagnostics, diff, and
    the 16 |terminal| colors.
  - Variables and properties use normal text; functions blue, types yellow,
    keywords green, and strings cyan. Delimiters use secondary text.
  - Line numbers use fg_subtle (4.66:1 on bg), below comments (5.23:1) and
    body text (6.52:1). Inactive statuslines retain fg_dim on bg_alt.
  - Visual uses a low-chroma background with a light foreground (7.61:1),
    replacing syntax colors while selected to keep comments readable.
    LSP references use a quieter background and an underline.
  - Surface separation is checked separately from text contrast.

2. REQUIREMENTS                                   *dim-solarized-requirements*

  - Neovim 0.9.5 or later. CI checks 0.9.5, 0.10.4, 0.11.5, 0.12.5,
    stable, and nightly. Nightly is a compatibility probe.
    The runtime uses nvim_set_hl (since 0.5); tests use nvim_get_hl and
    the -l runner (since 0.9). Older untested versions are not supported.
  - 24-bit color: `vim.o.termguicolors = true`

==============================================================================
3. INSTALLATION                                   *dim-solarized-installation*

With lazy.nvim: >lua
    {
        "pitahashi/dim-solarized.nvim",
        lazy = false,
        priority = 1000,
        opts = {},
    }
<
`lazy = false` and `priority = 1000` ensure the colorscheme loads before your
other plugins. lazy.nvim passes `opts` to |dim-solarized.setup()|.

==============================================================================
4. USAGE                                                 *dim-solarized-usage*
>lua
    vim.cmd([[colorscheme dim-solarized]])
<
>vim
    colorscheme dim-solarized
<
|dim-solarized.setup()| is optional. Without it, the defaults are used.
|:colorscheme| always sets 'background' to `dark`; there is no light variant.

==============================================================================
5. CONFIGURATION                                 *dim-solarized-configuration*

Configure the colorscheme BEFORE loading it. If |dim-solarized.setup()| is
called afterwards, the options won't take effect until you run
`:colorscheme dim-solarized` again. >lua

    require("dim-solarized").setup({
        transparent = false,
        italic_comments = true,
        on_colors = function(c) end,
        on_highlights = function(c, groups)
            return {}
        end,
    })
<
                                                    *dim-solarized-options*
transparent        boolean (default: false)
                   Make the backgrounds of Normal, NormalNC, NormalFloat and
                   related groups transparent.

italic_comments    boolean (default: true)
                   Italicize comments.

on_colors          fun(c) (default: no-op)
                   Modify the palette `c` in place before highlights are
                   built. See |dim-solarized-overrides|.

on_highlights      fun(c, groups): table (default: returns `{}`)
                   Add or override highlight groups. See
                   |dim-solarized-overrides|.

`on_colors` and `on_highlights` are ignored if they aren't functions.

==============================================================================
6. OVERRIDING COLORS AND HIGHLIGHTS                  *dim-solarized-overrides*

`on_colors` gets the palette `c` and edits it in place. The result is used by
the highlight groups, the |terminal| colors, and the bundled lualine theme.
>lua

    require("dim-solarized").setup({
        on_colors = function(c)
            c.bg = "#001f27"
        end,
    })
<
`on_highlights` gets the palette `c` (after `on_colors`) and `groups`, the
built-in definitions. It returns a table of `group name = nvim_set_hl
definition`. >lua

    require("dim-solarized").setup({
        on_highlights = function(c, groups)
            return {
                CursorLine = { bg = c.bg_sel },
                ["@comment.todo"] = { fg = c.orange, bold = true },
            }
        end,
    })
<
Notes:

  - A returned group replaces the built-in definition entirely; attributes
    are not merged. To change only `fg`, repeat any `bg` or `bold` you want
    to keep. The built-in definition is available as `groups.<name>`.
  - Returned values are applied last, so they win over `transparent`.
  - The palette passed to the callbacks is a copy. Changing it doesn't
    affect anything else.

To style a plugin this colorscheme doesn't cover, add its groups with
`on_highlights`.

7. PALETTE                                             *dim-solarized-palette*

Keys available in `c`:

  bg, bg_alt, bg_sel, bg_float   Normal background, cursor line and similar,
                                 selection, floating windows
  fg, fg_dim, fg_subtle,         Normal, secondary, auxiliary UI,
  fg_bright                       emphasized foreground
  comment, border                Comments, borders
  yellow, orange, red, magenta,
  violet, blue, cyan, green      The 8 accents
  diff_add, diff_change,
  diff_delete, diff_text         Diff backgrounds

The six ANSI normal/bright accent pairs intentionally share colors to avoid
extra bright accents. Applications that rely only on this distinction lose
it. Black/bright black and white/bright white remain distinct. ANSI black is
a surface color, not readable text on bg.

Default contrast targets assume opaque backgrounds. Transparent mode and
user overrides depend on the terminal background. Selected syntax uses
fg_bright; raw comment color on bg_sel is not a supported text pairing.

8. API                                                     *dim-solarized-api*

                                                       *dim-solarized.setup()*
require("dim-solarized").setup({opts})
    Apply user options. Call before running `:colorscheme`.

    Parameters: ~
      {opts}  (table|nil)  Options to override. See |dim-solarized-options|.

                                                      *dim-solarized.colors()*
require("dim-solarized").colors()
    Return a copy of the palette with `on_colors` applied.

    Return: ~
      (table)  Palette keyed as in |dim-solarized-palette|.

                                                        *dim-solarized.load()*
require("dim-solarized").load()
    Apply the colorscheme. Called by `:colorscheme dim-solarized`.

==============================================================================
9. TROUBLESHOOTING                             *dim-solarized-troubleshooting*

  - Colors aren't applied: make sure |dim-solarized.setup()| runs before
    `:colorscheme` and that 'termguicolors' is on.
  - Colors from another colorscheme show through: with lazy.nvim, make sure
    `lazy = false` and `priority = 1000` are set.
  - Options changed after loading have no effect until you run
    `:colorscheme dim-solarized` again.

11. VALIDATION                                      *dim-solarized-validation*

From the repository root, run the Lua tests (no external dependencies): >
    nvim -l tests/run.lua
<
Check rendered colors with the bundled Lua Tree-sitter parser and a fixed
LSP server fixture (requires Python 3, standard library only): >
    nvim -l tests/render.lua
<
Repeat with an installed Lua Language Server: >
    nvim -l tests/render.lua --real-lsp
<
Both modes read actual Neovim UI colors at 16 positions in six scenes:
Tree-sitter alone, combined semantic tokens, linewise selection, deselection,
characterwise selection, and blockwise selection. All selected text uses
fg_bright on bg_sel; syntax colors return after deselection.

Both modes passed locally on Neovim 0.9.5, 0.10.4, 0.11.5, and 0.12.6,
using LuaLS 3.18.2-dev for the real-server check. CI includes the fixed-server
test.
